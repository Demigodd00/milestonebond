# MilestoneBond v0.3 reviewer guide

MilestoneBond is a standalone, test-only GenLayer app for staged software delivery. It uses simulated StudioNet GEN, is not audited, and is not suitable for real-value escrow. The v0.3 policy is an explicitly **sponsor-approved, unmerged commit**—not a claim that code merged. The sponsor and author use distinct wallets; the author wallet is bound to a frozen GitHub account and exact PR-body claim. Validators independently re-fetch the public source and compare criterion verdicts before a tranche can be credited.

## Start here — no wallet needed

1. [Open the app](https://demigodd00.github.io/milestonebond/). The hero diagram and walkthrough are illustrative. The **Verify the live run** section links to the actual v0.3 transactions.
2. Open **Live projects** and select `MB-LIVE-002`. The app reads the [v0.3 contract](https://explorer-studio.genlayer.com/contracts/0xa3Cb18a9846a49aF882Cae38fB79923D7F6DcC34) directly; the two stages should show `ACCEPTED` and the project `COMPLETE` while StudioNet retains state.
3. Read the [machine-readable verification record](../public/verification.json) and [steward response](STEWARD_FIXES_V03.md). The former checks onchain source, frozen evidence hashes, each finalized receipt, the native child transfer, and final accounting. It records one deliberately failed pre-approval review and one deliberately failed wrong-parent reconciliation as failures, not as successful steps.
4. Inspect [issue #1](https://github.com/Demigodd00/milestonebond/issues/1), [PR #2](https://github.com/Demigodd00/milestonebond/pull/2), [PR #3](https://github.com/Demigodd00/milestonebond/pull/3), and their fresh [stage-one](https://github.com/Demigodd00/milestonebond/actions/runs/38197462942/attempts/2) and [stage-two](https://github.com/Demigodd00/milestonebond/actions/runs/38198377989/attempts/2) CI attempts. Check the exact `MilestoneBond-Claim` lines and the onchain sponsor approvals before interpreting the validator verdicts.
5. Compare the [withdrawal parent](https://explorer-studio.genlayer.com/transactions/0x2eb73e68d42db8fc74a2f5e44372f0dd86da65a5d23d6ceeffb88c96ac6faac6), [triggered native child](https://explorer-studio.genlayer.com/transactions/0xf8d01660e706e44d976cedc5c612156d8dd3a6f0307ff802aa3ab6e67f6c14bc), [wrong-parent rejection](https://explorer-studio.genlayer.com/transactions/0x266314bedf989710d5412a7b807a2eb716947dc7d7fbe4f91bf30349e55ea726), and [correct reconciliation](https://explorer-studio.genlayer.com/transactions/0x09c68d91a3800464fec4cdf55d2384c92cc805f0044e31ce04d6d8f81baa9c6a). The child must be finalized with `value_credited=true`; the final accounting shows one 0.002 test-GEN payout and zero pending entitlement.

The [contract source](../contracts/milestone_bond.py), [33 direct tests](../tests/direct/test_steward_protections.py), [architecture](ARCHITECTURE.md), and [security limitations](SECURITY.md) are in this dedicated repository. The v0.3 deployed source SHA-256 and exact runner dependency are pinned in [the deployment record](../deployments/studionet_v0.3.json). A challenge-window `ACCEPTED` verdict alone is not a payout; the separate finalization must succeed.

## Historical run and boundaries

The earlier [v0.2 timeline](LIVE_DEMO.md), [v0.2 contract](https://explorer-studio.genlayer.com/contracts/0xb437593b7656254226ce496bc6f9A052A11D6345), and [archived verification JSON](../public/verification-v0.2.json) remain available. They are **not** evidence that the v0.3 sponsor, GitHub-author, or withdrawal-reconciliation protections existed in v0.2.

The direct adversarial tests mock GitHub, LLM and RPC data; they cannot reproduce a failed protocol child transfer. The live v0.3 happy-path child and the negative parent-hash probe are finalized onchain, but they do not prove donor-funded recovery after a real failed child. Ambiguous transfers remain pending rather than allowing automatic duplicate payout. GitHub account association, CI runner/dependencies, StudioNet RPC, validator availability, and sponsor-authored criteria remain external trust dependencies. A dated verification JSON is historical if StudioNet resets.

## Try the signing path

Use a test-only EIP-1193 browser wallet on StudioNet, chain ID `61999`. Fund the same signing address with simulated GEN through GenLayer Studio's faucet before creating a project. The site checks the verified v0.3 address, onchain config and source hash before signing. The author must put the displayed exact claim in an open, unmerged PR, submit a fresh passing CI attempt, then wait for separate sponsor approval, validator review, challenge-window finalization and, for withdrawals, child-transfer reconciliation. The public completed demo needs no wallet or funding to inspect.
