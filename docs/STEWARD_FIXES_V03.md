# Steward concerns — MilestoneBond v0.3

This release is a new StudioNet deployment, not a mutation of v0.2. The [v0.3 contract](https://explorer-studio.genlayer.com/contracts/0xa3Cb18a9846a49aF882Cae38fB79923D7F6DcC34) was deployed by [this finalized transaction](https://explorer-studio.genlayer.com/transactions/0x0f83ef509e1be6ea65b2cdf969c53fc667958254cfff4d3da079382c661cfe9e); the [deployment record](../deployments/studionet_v0.3.json) pins the source SHA-256 and policy.

## 1. Delivery verification

Policy: `SPONSOR_APPROVED_UNMERGED_COMMIT`. A merged PR is **not** required or claimed. The PR must be open and unmerged when the assigned wallet submits and when validators review. The distinct sponsor wallet must call `approve_submission` for the exact captured evidence SHA-256 and revision before review. The validator re-fetches the public issue, PR, commit, workflow, CI attempt and complete bounded source and rejects any changed capture. Stage progression still waits for an accepted semantic verdict and a separate finalization after the challenge window.

## 2. Contributor attribution

Registration freezes the assigned author wallet plus GitHub login and numeric user ID, checked against GitHub `/users/{login}`. The wallet must accept and submit. The PR owner and GitHub-associated commit author must match that frozen user ID, and the PR body must contain exactly one `MilestoneBond-Claim: <project ID> <wallet lowercase> <head SHA>` line. The sponsor's separate approval binds the resulting evidence hash. These controls prevent a stranger wallet or unrelated GitHub PR from earning the tranche under the stated trust model. They do not prove real-world identity, prevent a repository maintainer from editing a PR body, or turn GitHub's association of an unsigned commit into a cryptographic signature.

## 3. Native GEN withdrawal safety

`withdraw(request_id)` moves credit to `pending_out`, never directly to `withdrawn`, and allows only one globally pending transfer. Request IDs cannot be reused. `reconcile_withdrawal(parent_hash)` independently fetches StudioNet's finalized parent and exact triggered child under strict equivalence, checks request ID/timestamp/sender/contract/recipient/amount/linkage, and accepts only an explicit boolean `value_credited`. A successful child records payout once. A missing, unfinalized or mismatched receipt leaves the entitlement pending without a second transfer. A finalized child that did not credit can restore claimable credit only when current contract balance covers all obligations; a separate payable `top_up_recovery` supplies replacement simulated GEN if needed. The donor does not gain a refund claim.

This prevents accounting-level duplicate payouts and preserves a pending entitlement under ambiguity. It cannot force a broken protocol to produce a child receipt or replace GEN lost by the protocol; such a case stays pending until conclusive evidence and, for a failed child, actual balance coverage. The StudioNet RPC used by validators is an external trust dependency. This is not production-value insurance or an audit.

## Tests and live evidence

`pytest tests/direct -q` exercises 33 cases, including no sponsor approval, wrong evidence hash, non-sponsor approval, merged PR, foreign PR/commit GitHub IDs, missing wallet claim, changed PR after approval, missing/mismatched/unfinalized child receipts, replayed request IDs, and failure with insufficient balance until a top-up. Direct mode mocks GitHub, the LLM and receipts; it does not prove live GenLayer consensus or an actual failed native transfer. `pnpm test`, `pnpm build`, and `genvm-lint check contracts/milestone_bond.py --json` provide frontend, build and contract validation.
