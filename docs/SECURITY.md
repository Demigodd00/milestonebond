# Security and reviewer limitations

MilestoneBond v0.5 is a Bradbury testnet prototype with test GEN. It is not audited and must not be used with real-value assets. The v0.4/v0.3 StudioNet deployments remain archived and must not be mistaken for the current contract.

Critical external trust remains with GitHub availability, repository control, workflow configuration, CI runner/dependency integrity, and the meaning of sponsor-authored criteria. A repository owner could weaken tests before the commitment; the contract freezes workflow content, not the quality of its external dependencies. GenLayer validators provide independent retrieval and semantic agreement, not proof that code will behave safely in deployment.

This release intentionally restricts patches to a single direct-child commit, 1–4 modified allowlisted existing files, 24 KB of complete source, same-repository open/unmerged PRs, and a successful pinned push workflow. The PR owner and GitHub-associated commit author must match the registered GitHub user ID; the PR body must claim the exact assigned wallet and head. GitHub can associate unsigned commits with an account by email, and repository maintainers may edit PR bodies. The wallet-signed submission and separate sponsor approval of the exact captured hash are therefore essential, but these checks do not establish real-world identity or independent human approval. Large changes, forks, merge commits, changed workflows, binary files and missing evidence are unsupported. Do not work around a rejection by claiming a simulated result is live.

The v0.5 contract does not mark a withdrawal paid at submission. It keeps a pending entitlement until validators independently fetch the finalized GenLayer parent, exact external message, EVM finalization receipt and linked failure/settlement events. A matching failure restores claimable credit only when the real balance covers all obligations; an unreturned shortfall may consume only this project's remaining sponsor-funded reserve. Any excess shortfall requires sponsor top-up, and ambiguous or inaccessible evidence remains pending rather than authorizing a second transfer. The contract cannot manufacture lost protocol funds. The [Bradbury live run](BRADBURY_V05_RECOVERY.md) demonstrates one rejected EVM transfer and restored credit with no reserve consumption or duplicate payout. Reserve-consuming recovery after a live unreturned loss and production-value safety are **not** demonstrated. Bradbury RPC, EVM event semantics and validator availability remain external trust dependencies.

Do not put account keys, GitHub tokens, private issue text, or personal data in terms or source. GitHub source and issue bodies are public and may be copied into onchain evidence. Report security issues privately to the repository owner rather than publishing exploit details.
